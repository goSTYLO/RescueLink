# Module 11 – Prototype Sprint 2  
**Feature Expansion & Integration**  
- Expand project functionality.  
- Integrate external APIs/microservices.  
- Document technical progress for scalable systems.  

---

## Session Objectives  
- **Feature Expansion** → Add at least one new feature to enhance functionality and user value.  
- **System Integration** → Integrate an API, microservice, or external tool.  
- **Technical Documentation** → Show new functionality and integration test results.  

---

## Bridge Recall (Start of Lesson – 10 min)  
Prompts:  
1. Define “Bottleneck” – What does it mean in system performance/data flow?  
2. Previous Fix & Metrics – What fix was applied last time, and what metric improved (time, gas, memory)?  
3. Scaling Strategy – Which scales better for 10x users: caching or vertical scaling? Why?  

---

## Concept Overview – Feature Expansion & Integration  
- **Why Expand?** → Sprint 1 proves core feature; Sprint 2 makes it functional for real-world users.  
- **Integration Basics:**  
  - API → Connects apps (e.g., weather widget in chatbot).  
  - Microservice → Independent add-on (e.g., payments).  

**Prototype Evolution:**  
- Sprint 1 → Core Feature Proof-of-Concept  
- Expansion → Add functionality & utility  
- Integration → Connect APIs & services  
- Useful Product → Real user value  

---

## New Concept – Agentic AI  
- **Definition:** AI that takes actions step by step, makes decisions, uses tools/APIs.  
- **Why It Matters:**  
  - Smarter & autonomous.  
  - Efficiency → Automates workflows.  
  - Real-world connection → Actionable outputs.  
  - Multi-step capability → Complex assistants.  

**Mini-Case: WhatsApp Expansion**  
- Messaging → Voice → Group Calls → Payments  
- Reflection: What bottleneck/user need led to this expansion?

## Activity (35 min) – Sprint 2 Planning Framework  

**Goal:** Create roadmap before coding.  

**Instructions:**  
1. Select Features → One new feature + one integration.  
   - AI: Translation, summarization, API  
   - Blockchain: History, access control  
2. Sketch Flow → Input + Process + Output.  
3. Fill Planning Table.  

**Sprint 2 Plan Table**  

| ITEM CATEGORY | DESCRIPTION & DETAILS |
|---------------|------------------------|
| New Feature – What will you add? | Example: Add “Save to Favorites” button for generated images |
| Integration – API/Tool/Service | Example: OpenWeatherMap API for local conditions |
| Success Criteria – How do we know it works? | Example: Clicking button saves item to local storage and appears in “Favorites” tab |
| Risks & Fixes – Potential issues? | Example: API limit exceeded → Cache responses locally for 1 hour |

## Session 2 – Build Phase  

**Activity Goal:** Build feature, test 3 cases.  

**AI Track:**  
1. Recreate demo OR adapt planned feature.  
2. Test 3 inputs before/after feature to verify improvement.  

**Blockchain Track:**  
1. Recreate demo OR add new contract function.  
2. Test 3 cases in Remix IDE.  

**Verification – Before vs After Table**  

| TEST CASE / SCENARIO | BEFORE STATE | → | AFTER STATE | IMPROVEMENT TYPE |
|-----------------------|--------------|---|-------------|------------------|
| Chatbot Q&A | English responses only | → | Adds Filipino translation | EXPANDED FEATURE |
| Contract Storage | Only stores 1 message | → | Stores history of 3 messages | EXPANDED INTEGRATION |
| Your Test Case … | Current limitation … | → | New capability … | TO BE DETERMINED |
